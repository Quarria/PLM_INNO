# 商机模块功能设计方案 V1.0

日期：2026-11-04。范围：功能、交互与实现设计。首版已实现；升级与操作见《商机模块使用与升级指南》，验证记录见 `docs/ui-preview/opportunities/验收记录.md`。

## 1. 目标与边界

把一次客户合作机会归入一份商机档案，持续记录从打样到完成的进度、单据和操作历史。进入商机详情后，无需翻查单据即可知道当前节点。

已明确的需求：

- 可主动新建商机。
- 固定五个节点：打样 → 送样 → 客户反馈 → 合同 → 完成。
- 每个节点可录入单据。
- 由人员手动推进至下一节点。
- 每次打开详情均展示当前节点状态。

现有系统事实：已有客户、品牌、产品规格、报价、账号及角色权限；已有产品图片上传，但没有可直接复用的商机节点单据模块。现有媒体目录通过 `/media/` 静态开放。

首版采用以下规则：新建默认进入打样；节点不强制有附件才能推进；客户反馈不通过可退回打样；完成表示商机跟进成功结案，不自动表示已出库、已交付或已回款。若后续需要以交付或回款作为完成标准，应同步调整完成条件。

## 2. 核心业务模型

### 2.1 商机基本信息

| 字段 | 规则 |
| --- | --- |
| 商机编号 | 系统生成、唯一、不可编辑，例如 SJ20261104-0001 |
| 商机名称 | 必填，例如“某客户便携风扇贴牌合作” |
| 客户 | 必选，关联现有客户；新客户沿用现有客户建档权限 |
| 负责人 | 必填，默认创建人，可授权转交 |
| 需求描述 | 可选，允许产品尚未建档时描述定制需求 |
| 关联商品 | 可选、多选到产品规格；一个商机内商品共用一条流程 |
| 预计金额、预计完成日期 | 可选；预计金额不等同于合同金额 |
| 关联报价 | 可选、多份；校验客户一致；关联不改变报价确认规则 |
| 当前节点、业务状态 | 系统维护，禁止通过普通编辑接口直接改写 |
| 创建人、创建及更新时间 | 系统记录 |

若多件商品需要独立推进，建议拆成多个商机；首版不增加商品级子流程。

### 2.2 分开记录节点和结果

- 当前节点：打样、送样、客户反馈、合同、完成。
- 业务状态：跟进中、已完成、已终止。
- 节点显示：未开始、进行中、已完成；退回造成的旧节点执行记录显示“已退回”。
- 跟进中只允许前四个节点有一个进行中；进入完成节点时，业务状态同时变为已完成。
- 完成节点是结案档案，可在结案时及结案后补录单据，无需再点一次完成。
- 终止不改变最后停留节点，明确显示“已终止 · 停留在客户反馈”等；不得将终止商机标成完成。

## 3. 页面与主操作

### 3.1 商机列表

在主导航增加“商机管理”，沿用现有页面的表格、筛选和按钮样式。

- 主操作：新建商机。
- 筛选：关键词（编号、名称、客户）、负责人、当前节点、业务状态。
- 表格列：编号/名称、客户、负责人、当前节点、状态、当前节点停留天数、预计金额、最近更新时间、查看。
- 默认展示跟进中商机，提供“全部”筛选；默认按最近更新时间倒序。
- 新建保存成功后进入详情；创建失败保留输入，不显示虚假的已创建记录。

### 3.2 商机详情

采用独立详情工作区，顶部保留返回列表。内容顺序：商机概况 → 五节点进度条 → 所选节点的单据 → 操作历史。

```text
← 商机列表    SJ20261104-0001  某客户贴牌合作
客户：某客户    负责人：张三    状态：跟进中
当前节点：客户反馈    本轮进入：11月04日    已停留：2天

✓ 打样 ── ✓ 送样 ── ● 客户反馈 ── ○ 合同 ── ○ 完成

客户反馈    本轮进行中                    [新增单据] [推进至合同]
单据名称       类型       业务日期       录入人       附件
样品试用意见   客户反馈   2026-11-04     张三         查看 / 下载

操作历史：进入节点、推进、退回、单据补录/作废、转交、终止、结案
```

- 每次打开先从服务端读取最新详情，默认选中当前节点，不沿用上次选中的历史节点。
- 点击其他节点只切换查看内容，不改变业务进度；顶部始终保留真实当前节点。
- 已完成节点可查看及补录单据，明确标记“补录”；未来节点可查看空状态，暂不允许录入。
- 已退回重走的节点按轮次分组，默认展示最新一轮，可展开历史轮次。
- 推进成功后，更新概况和进度条，并选中新节点；失败时保留当前内容和输入。
- 小屏将步骤条横向滚动，保留节点文字、状态和当前节点摘要，不能只依赖颜色。

## 4. 各节点单据设计

“单据”采用可多次新增的业务记录，每条记录可带零个或多个附件，不等同于只能上传一份文件。

| 节点 | 建议单据类型 | 可补充的业务信息 |
| --- | --- | --- |
| 打样 | 打样需求、打样记录、样品照片、检测报告 | 关联产品、打样数量、预计完成日期 |
| 送样 | 送样单、快递凭证、签收记录 | 收件人、寄出日期、快递公司、运单号 |
| 客户反馈 | 反馈记录、测试结果、修改要求 | 反馈结论：通过/需修改/不通过/待明确 |
| 合同 | 合同草稿、已签合同、补充协议、关联报价 | 合同编号、金额、签订日期 |
| 完成 | 结案说明、交接资料、其他凭证 | 完成日期、结果说明 |

通用必填：单据名称、单据类型、业务日期。通用可选：说明、附件及该类型的业务字段。系统自动记录编号、所属商机/节点/轮次、录入人和录入时间。送样、合同等特有字段首版按需填写，不据此隐式触发其他模块。

建议支持 PDF、PNG/JPEG、DOCX、XLSX，单文件上限 20 MB；具体范围可配置。文件数量、总请求大小和单据字段需由服务端限制；类型同时校验扩展名和文件内容，不接受可执行文件。

已保存单据原则上保留历史：允许作废并填原因，修正时新增替代单据并关联原记录。已使用的附件不直接覆盖。未来若增加草稿，再单独允许草稿编辑删除。

## 5. 手动流转规则

### 5.1 正常推进

1. 当前节点点击明确的动作，例如“完成打样，推进至送样”。
2. 弹窗展示当前节点、目标节点、有效单据数量，可填写推进说明。
3. 没有有效单据时提示补录；仍可推进，但必须填写无单据原因。附件本身不作为必填项。
4. 确认后在同一事务内结束当前执行记录、开启下一节点记录、更新商机当前节点并写入操作历史。
5. 合同节点的动作改为“完成商机”，必须填写结案说明；同时进入完成节点、记录完成时间并将商机标为已完成。

首版不支持跳节点，不增加审批流。客户反馈不通过/需修改时仍允许人工决策，但推进合同须提示并填写原因；系统不能自动把负面反馈改成通过。

### 5.2 退回与重新打样

- 负责人或管理人员可退回任一已到达的前序节点，必须填写原因。
- 例如客户反馈 → 打样：旧客户反馈执行记录标为已退回，新开一次打样执行记录；原打样、送样和反馈单据全部保留。
- 进度条按当前一轮显示：打样进行中，后续节点待重新进入；历史已完成记录在轮次与日志中保留。
- 后续仍须按顺序推进。当前节点停留时长从本轮进入时间计算，不混入上一轮。
- 已完成、已终止不允许普通推进或退回；首版不做重新开启，后续需要时通过独立受控操作实现。

### 5.3 终止

跟进中可终止，必须填原因，如客户取消或方案未通过。终止保留当前节点和全部资料，不能再修改原单据或流转；允许授权人员以补录方式增加说明资料，日志注明结案后补录。

## 6. 权限和一致性

- 建议新增 `opportunity:view`、`opportunity:create`、`opportunity:write`、`opportunity:manage`。
- 首版建议持有查看权限者可看全部商机；持有编辑权限的负责人可维护本人的商机，管理权限可跨负责人维护和转交。权限范围仍需业务确认。
- 新建时普通人员仅可指定自己为负责人；管理员/商机管理人员可指定其他有效账号。负责人停用前需转交跟进中商机。
- 单据新增、补录、作废、下载和流转均由服务端校验权限及所属商机，不能只隐藏前端按钮。
- 合同及客户资料采用鉴权下载接口；文件放在独立私有目录，不复用当前公开 `/media/` 地址。只有校验商机访问权限后才可读取文件。
- 每次推进/退回携带版本号，服务端锁定并检查版本和当前节点；并发重复操作只允许一次成功，过期请求提示刷新。
- 重复提交通过请求唯一标识防重，编号通过数据库唯一约束及序列生成，不能使用“记录数 + 1”。
- 文件上传失败不生成完整单据；上传暂存后在保存成功时关联，未关联临时文件按期限清理。数据库与私有文件一起纳入备份。

## 7. 实现落点

前端在 `frontend/src/App.vue` 增加导航及入口，独立新增商机列表、详情、节点单据和流转弹窗组件，复用现有样式变量、客户及商品选择能力。商机详情需有稳定的商机 ID 定位和返回逻辑；刷新后重新鉴权并读取详情。

后端单独增加商机 controller/service 和迁移，复用现有登录、权限装饰器、客户/商品/报价数据；不把商机状态塞进报价状态或库存状态。

建议数据结构：

| 表 | 作用与核心字段 |
| --- | --- |
| opportunities | 商机主表：编号、客户、负责人、需求、金额、状态、当前执行记录、版本、结案时间 |
| opportunity_items | 商机商品：产品规格及必要名称快照 |
| opportunity_stage_runs | 节点执行：节点代码、本节点执行次数、进入/离开时间、结果、前序执行记录 |
| opportunity_documents | 节点单据：所属执行记录、类型、名称、业务日期、扩展字段、作废/替代关系 |
| opportunity_attachments | 附件元数据：所属单据、私有存储键、原文件名、类型、大小、校验值 |
| opportunity_quote_links | 关联报价 ID；引用其现有版本，不复制或改写报价确认状态 |
| opportunity_events | 不可覆盖的操作历史：动作、前后节点执行记录、操作者、时间、原因、请求唯一标识 |

五个节点使用固定代码，不做可配置流程引擎。当前节点从主表关联的执行记录取得，禁止由最后上传单据推算，也不分别维护多个可冲突的当前节点标志。

建议接口：列表/创建/详情/基本信息修改；新增单据/作废单据；附件上传/鉴权下载；推进/退回/终止/转交。所有状态变更使用独立动作接口，普通 PATCH 不接受状态字段。

首版包括五节点、单据附件、手动推进、退回、终止、历史、权限及报价关联；暂不包括自动生成订单/库存单、电子签章、合同审批、回款管理、自动通知及销售预测。

## 8. 验收标准

1. 主动新建后可在列表查到，进入详情默认显示打样进行中，其余节点未开始。
2. 五个节点均可新增多张单据；已到达节点可补录，附件上传失败保留输入且不产生虚假成功记录。
3. 保存单据不会自动推进；正常推进一次仅进入下一节点，刷新或重新进入后状态一致。
4. 查看历史节点不改变当前节点，详情顶部始终明确显示真实进度。
5. 无有效单据时必须填写原因才能推进；作废单据不计入有效数量。
6. 客户反馈退回打样后完整保留上一轮单据，新的送样和反馈属于新的执行记录。
7. 从合同完成商机后显示完成节点及已完成状态，可补录结案资料，不能再普通推进。
8. 终止商机显示终止原因和停留节点，不计为完成。
9. 两人同时推进仅一次成功；客户端重复提交不产生重复节点或历史。
10. 非负责人不能通过直接请求修改他人商机；无访问权限者即便知道附件 ID 也不能下载。
11. 关联报价不会绕过原有报价确认和导出规则，且不自动创建订单或出入库记录。

## 9. 首版实施采用的业务口径

- “完成”采用成功结案定义，不以交付或回款作为自动判断条件。
- 接受无有效单据但填写原因后推进，合同结案必须填写说明。
- 按角色授权查看全部、按负责人限制修改；商机管理权限可跨负责人维护和转交。

以上口径作为首版实现与验收依据；后续若调整结案条件或数据可见范围，应同时调整服务端校验和验收用例。
