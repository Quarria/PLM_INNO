# 简易 PLM 系统技术选型与开发步骤

版本：V0.2（评估稿）  
日期：2026-11-01  
状态：待确认；尚未开始开发

## 1. 建议技术组合

- 前端：Vue 和 TypeScript，负责产品、客户、价格规则及报价页面。
- 后端：Node.js 和 TypeScript，负责账号权限、业务规则、价格计算、报价确认和 Excel 导出。
- 数据库：使用现有云端 PostgreSQL，通过受限账号和环境配置连接；应为本系统准备隔离的数据库或经授权的独立空间。
- 部署：Windows、Linux 或 macOS 上运行一个应用服务，前端打包文件由后端提供；用户从公司局域网访问运行电脑的 IP 和端口。
- 附件：产品图片存储在运行应用的电脑；数据库和图片都需备份。
- 输出：以现有参考文件为依据导出 Excel 报价单。

该组合是针对现有条件的建议，并非必须使用的唯一技术。前后端在同一项目中分目录组织；开发阶段可分别运行，日常部署尽量简化。正式使用时以适合运行环境的 Node.js 服务运行，监听范围限制在公司网络。跨平台安装与启动方式要在三种系统上分别验证，不能仅凭技术选型视为已实现。

## 2. 项目目录建议

```text
frontend/    页面与交互
backend/     接口、计价、权限和 Excel 导出
docs/        需求、部署及使用说明
```

业务数据、图片、连接密钥与源代码分开管理；不得将数据库凭据放进代码仓库。运行电脑需在使用时开机，局域网可达并能连接云数据库。

## 3. 系统模块与依赖顺序

1. 项目基础：统一配置、登录、用户角色、数据库连接、日志、文件目录和跨平台启动方式。
2. 基础资料：商品与规格、组成关系、图片、客户及品牌。
3. 基础价格：采购基准价／出厂价、财务含税成本及市场零售参考价。
4. 价格规则和计算：固定单价、固定金额加价、百分比加价、折扣；整批及分段计算；组合商品及缺价处理。
5. 报价流程：自有品牌与贴牌两个页签、按需建价、长期／本次调价、逐产品确认、快照与版本。
6. Excel 导出：参考现有两类报价表，维护条款并展示适用数量档与计算结果。
7. 交付验证：权限、典型价格场景、局域网访问、云数据库异常、备份恢复及跨平台运行。

开发时应优先打通“录入一个商品 → 设置阶梯 → 创建报价 → 确认 → 导出”的完整链路，再扩展组合商品和客户专属场景，以尽早验证使用体验。初始数据导入不在首期。

## 4. 关键验证

- 数量边界、阶梯冲突、整批／分段计算、单价与金额舍入。
- 组合商品数量换算、缺少基础价时直接录价、固定价与百分比价对基准价变化的不同反应。
- 同产品所有展示档一次确认；任一档变化后重新确认；已确认报价保留快照。
- 客户规则按需创建，本次价格不影响长期规则；成本与内部计算依据不进入对外导出。
- 两名用户并发调整价格或确认报价时避免覆盖或确认过期数据。
- 数据库不可用时明确提示，失败操作不显示为成功；备份包含数据库和图片，且恢复经过验证。
- 导出的 Excel 可使用常见表格软件打开，金额及条款与已确认报价一致。

## 5. 开发前需最终确定的规则

1. 金额默认人民币、含税与否、税率、运费、单价和金额保留位数及舍入方式。
2. 百分比和折扣如何输入；固定加价、百分比加价、折扣和固定单价每档选择一种的规则是否确认。
3. 参考表上的建议零售价取哪个市场参考价，建议首批量如何维护。
4. 自有品牌是否可分别为同一商品配置价格；客户多个品牌是否需要不同规则。
5. 业务员能否确认自己制作的报价；角色具体权限。
6. 组合商品是否允许嵌套、能否设置独立阶梯规则以及与组成计算的优先级。
7. Excel 的商务条款默认值、数量档展示与正式报价／参考报价的标识。
8. 数据库访问权限、隔离方式与备份能力；实际运行电脑和网络条件。

这些问题可以逐项确认；未定内容不应被静默当作正式报价规则。数据库账号和密码仅在执行配置时通过安全方式提供，此阶段无需提供。
