# 商机模块使用与升级指南

## 业务口径

商机按“打样 → 送样 → 客户反馈 → 合同 → 完成”顺序推进。完成表示商机成功结案，不自动表示已交付、出库或回款，也不自动创建销售订单。

保存单据不会推进节点。无有效单据时，填写原因后可手动推进；合同进入完成时必须填写结案说明。客户反馈不通过或需修改时，可退回打样开启新一轮，旧单据保留。

## 升级

1. 备份目标数据库、现有商品图片，以及商机私有附件目录（后续升级时）。
2. 核对 `backend/.env` 指向预期数据库及 schema。
3. 在项目根目录运行 `npm run typecheck` 和 `npm run build`。
4. 停止旧版本服务，运行 `npm run migration:run -w backend`，再启动新版服务。
5. 使用管理员账号检查“商机管理”入口和“用户与权限”中的商机权限。

迁移新增商机表及编号序列，不自动删除已有报价、客户、库存和订单。迁移的回滚入口不会自动删除商机历史；恢复旧版本应根据备份制定恢复步骤。

商机附件须放在私有目录，通过登录后的下载接口访问，不能移动到公开的 `/media/` 目录。数据库和私有附件需一起备份并验证恢复。

目录通过 `OPPORTUNITY_FILES_DIR` 配置，默认是后端运行目录下的 `data/opportunities-private`。支持 PDF、PNG/JPEG、DOCX、XLSX，单文件不超过 20 MB，每张单据最多 10 个附件。未绑定单据且超过 7 天的暂存附件，会在后续上传时清理。

## 权限

| 权限 | 用途 |
| --- | --- |
| 查看商机与节点单据 | 查看商机列表、详情和单据附件 |
| 创建商机 | 新建商机，普通人员默认由自己负责 |
| 维护本人负责的商机 | 修改本人负责的跟进中商机、录单及推进 |
| 管理全部商机与转交负责人 | 跨负责人维护及转交 |

管理员具有全部权限。业务员需要查看、创建和维护本人商机权限；商机管理人员另加管理权限。可查看全部商机与可修改全部商机是两种不同权限。

## 操作

1. 打开“商机管理”，点击“新建商机”，填写名称、客户、负责人等信息。可关联已有产品规格和同客户报价。
2. 创建后进入详情，顶部显示真实当前节点，默认展开当前节点单据。
3. 在节点中新增单据，填写名称、类型、业务日期、说明，可添加多个附件。失败时保留输入，处理提示后重试。
4. 完成当前工作后，点击推进按钮；核对目标节点并确认。历史中会记录人员、时间和说明。
5. 需要重新打样时，选择退回已到达的前序节点并填写原因。按轮次查看历史资料，不覆盖原记录。
6. 点击已到达节点可补录资料；点击未来节点不会推进，也不能提前录单。
7. 合同达成后点击“完成商机”并填写结案说明。完成后可补录结案资料，不能继续普通流转。
8. 客户取消等情况下使用“终止”，填写原因。终止商机保留停留节点，不计入已完成。

单据错误通过作废并重新录入修正，保留原始记录；成功结案或终止后不再作废已有单据。商机转交保留历史操作者。

## 常见提示

- **记录已更新或版本过期**：其他人员已操作，刷新详情，核对当前状态后再决定下一步。
- **无有效单据**：补录单据，或填写原因后继续；作废单据不计入有效数量。
- **没有维护权限**：检查本人是否为负责人，以及是否拥有相应权限。
- **报价客户不一致**：只能关联当前客户的报价，报价本身仍走原有确认与导出流程。
- **附件上传失败**：检查文件类型、大小和连接状态；不要将上传成功等同于单据已保存。

## 验证方式

商机集成测试使用随机隔离 schema 和临时附件目录，不以正式业务表作为测试数据。生产升级仍需独立执行迁移、重启和业务抽查。

在项目根目录运行 `npm run test:opportunities -w backend`。测试需要可访问已配置的 PostgreSQL，且账号能新建测试 schema。测试使用 3108 端口，可通过 `OPPORTUNITY_TEST_PORT` 更换，结束后清理随机测试 schema 和临时附件目录。
