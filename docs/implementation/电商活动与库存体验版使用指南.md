# 电商活动与库存体验版使用指南

日期：2026-11-03。设计依据见[模块设计方案](../architecture/电商活动与库存追溯模块设计方案-V1.0.md)。

## 1. 升级和入口

项目根目录安装依赖并构建：

```sh
npm ci
npm run build
```

确认 `backend/.env` 指向预期数据库，备份后执行新增迁移，再启动服务：

```sh
npm run migration:run -w backend
npm run start -w backend
```

已有数据库不需要重复初始化或创建管理员。新迁移增加物料编码和独立业务表，不会将历史商品当作已有实物库存；旧商品自动获得唯一物料编码，实际库存需办理期初入库。

访问 `http://localhost:3000`。管理员可看到“电商活动”“销售订单”“库存与出入库”。其他角色在“用户与权限”授予“查看活动、销售与库存”，并按需授予活动维护、销售维护、库存维护权限。

## 2. 推荐体验顺序

1. 在产品资料中检查型号、物料编码及单位。物料编码可在首次入库前调整，发生实物记录后限制修改。
2. 在库存与出入库办理期初或采购入库，填写生产批号及厂家序列号，每行一个序列号。序列号数量即本次入库件数，保留前导零。
3. 实体套装可整套入库，或选择现有组成件办理组装。已有组成模板时按模板校验，实际组成关系按具体序列号记录。
4. 在电商活动维护平台店铺，新增活动、商品标价和优惠规则。立减、百分比减免及满额减免按配置顺序计算，支持封顶、互斥组和承担方。百分比字段表示“减免百分比”，例如九折填写 10%。
5. 测算活动优惠。预计到手价仅作为方案参考，实际成交需在销售订单中单独录入。
6. 新增销售订单，填写优惠前单价、数量、实际优惠、运费、买家实付、店铺及活动归属。优惠完整时金额必须核对一致；不清楚具体券金额时取消完整核对标记。
7. 销售出库关联订单并选择实际发出的序列号，填写原因、接收方、发货时间、运单及物流费用。订单可分多次发货，系统拦截重复和超量发货。
8. 在订单详情查看实付、优惠、退款和实际发货记录，在活动统计查看订单与优惠汇总。
9. 输入序列号、生产批次或关联业务信息查看追溯，检查入库、组套及出库全过程。

## 3. 退货、样品与套装

- 仅登记退款不会恢复库存；实物退回时办理退货入库，序列号和批号应与原实物一致，验收后转可用或报废。
- 寄样赠送使用寄样出库；需归还的使用借样出库，填写预计归还时间。借样归还同样先待检。
- 套装组成件在组装后不再计入独立可用库存，销售套装时不重复扣减。拆套保留套装身份和历史，释放实际组成件。
- 业务完成即过账并保留流水。错误单据不通过修改库存余额抹掉历史，需关联后续更正业务处理。

## 4. 数据口径和当前边界

- 无平台订单接口，成交、优惠和物流数据由人工录入；统计反映已录入业务，不代表平台自动同步结果。
- 实付、已知券明细和未拆优惠分别保存。未知优惠不得当作某张券的确定金额；补齐后核对实际实付。
- 订单级退款无法直接确定归属于哪款商品时，显示订单级金额，不虚构商品退款分摊。
- 套装、组成件分别保留身份；查看库存数量时不能简单将套装与其内部组成件相加。
- 多仓调拨、平台自动同步、完整财务结算、复杂跨店凑单和保质期管理不属于本次基础体验入口。
- 实际操作连接配置的数据库，会产生真实业务记录。体验示例请使用隔离环境；不要向正式数据随意录入测试订单。

## 5. 隔离集成验证

```sh
npm run test:operations -w backend
```

测试读取数据库连接后创建随机 `plm_ops_test_` 前缀 schema，在该 schema 执行迁移，启动独立端口的测试服务，再验证关键流程。结束时只清理本次创建的测试 schema，不写入现有业务表。数据库账号需要创建和删除该测试 schema 的权限。

测试覆盖优惠计算、金额核对、并发序列号安全、超量发货、退款与库存分离、退货、验收、组装拆套、追溯及借样归还等关键链路。类型检查和构建不能替代真实业务样例验收。
