## 1. 开发代理执行边界

本文是首期实现依据，结合[需求方案 V1.1](../requirements/简易PLM系统功能需求方案-V1.1.md)、[架构与实施方案 V0.6](../architecture/简易PLM系统架构与实施方案-V0.6.md)、[技术方案对比与选型 V0.2](../architecture/简易PLM技术方案对比与选型-V0.2.md)及[报价参考工作簿](../reference/毅诺采购合作参考报价单%20V1.0%2020261012.xlsx)阅读。如有冲突，优先采用本文明确标为“已确认”的最新规则；暂定规则不能覆盖用户后续指示。数据库连接信息不写入代码库；不对共享数据库、现有表或真实数据进行破坏性操作。开发、测试及迁移使用授权的隔离数据库或独立 schema，先验证目标。本地 PGlite 启动时自动初始化；云端数据库未连接，部署和迁移按根目录 README 的隔离 schema 流程执行。

## 2. 目标和范围

公司产品、配件、组合商品及价格资料分散，报价慢、口径不统一。系统集中管理商品及客户资料、采购基准价（即人工录入的出厂价）、财务含税成本、阶梯规则和客户报价，支持 Excel 导出。早期基础价可以不完整，但每次报价单中每个产品的所有对外展示档位必须由人一起确认。随着实际报价，按需积累客户贴牌规则。

首期包含产品/配件/组合商品、规格与组成、图片、客户与品牌、价格管理、组合计价、自有品牌与客户贴牌两个报价页签、按需积累规则、逐产品确认、历史快照、Excel 导出、角色权限和必要的备份恢复说明。首次生成报价时允许录入本次人工固定价格；报价生成后不提供本次报价内改价。首期不包含初始数据批量导入、包装物料字段管理、销售最小单位字段、自动确认报价、外网访问、离线工作。

## 3. 技术及运行约束

**已确认**：前端 Vue + TypeScript；后端 Node.js + NestJS + TypeScript；前期使用本地 PGlite，保留后期切换云端 PostgreSQL 的配置；一个仓库的 `frontend/`、`backend/` 分目录；应用部署在 Windows、Linux 或 macOS 电脑，同事从公司局域网通过该电脑 IP 和端口访问；前端构建后由后端提供；用户不足 10 人；Excel 输出。采用单体应用，不引入微服务。当前使用 npm workspaces，依赖版本已锁定在 `package-lock.json`。

数据库访问配置和应用密钥从环境获取，禁止提交真实凭据；数据库 TLS/网络访问按实际服务配置。使用专用低权限账号和隔离数据库或 schema，禁止无确认覆盖其他业务表。图片放应用主机的数据目录，路径可配置，限制文件类型、大小和访问权限。启动信息不输出凭据；不绑定公网访问，防火墙限制公司内网。数据库或网络不可用时明确提示，不能假装成功；不承诺离线操作。数据库和图片需分别备份并验证恢复，程序升级不得覆盖数据。不同操作系统分别验证启动和路径处理。

## 4. 概念与字段

### 4.1 商品与规格

商品类型为 `product` 产品、`accessory` 配件、`bundle` 组合商品。商品身份与组成关系分离，标准产品可有组成。商品可有多个规格，报价、单位及价格对应具体规格；同型号可以有单只和双只等不同规格。商品货号全局唯一；规格在同一商品下按规格描述唯一。商品字段：系统 ID、货号/型号、品名、类型、主图、备注、状态、创建/更新时间；规格字段：商品关联、规格描述、计价单位、状态。序号为展示顺序，不作业务标识。停用商品/规格不能新加报价，历史快照保留。

组成关系：父规格、子规格、每父单位用量；用量必须大于零且单位明确；禁止自引用和任意循环引用。首期组合商品可包含产品和配件，不允许组合商品嵌套。组合商品可维护独立阶梯价，优先使用独立价，否则展示组成项计算参考价；组成项价格缺失时允许业务员在报价创建时人工录入成品价格。库存、采购订单和包装物料不在范围。

### 4.2 客户及品牌

客户：名称、联系人、联系方式、备注、状态；名称重复时提示而不静默合并。品牌区分自有品牌与客户品牌，支持多个自有品牌；客户品牌归属客户。同一商品可按不同自有品牌设置不同价格；同一客户的不同贴牌品牌也可分别设置价格。未设置适用品牌价格时明确提示。

### 4.3 价格与口径

采购基准价和出厂价是同一个概念：从工厂获取、人工录入的基础价格。财务报含税成本是独立字段，允许缺失。直接计算的市场零售参考价为基准价 ×（1＋50%、80%、100%、180%），基准价缺失时可改为人工填写建议零售价，也可使用人工报价继续报价。报价候选价与最终经人工确认的报价分别保存，不能因数字相同而视为已确认。价格需关联规格、单位、币种、含税口径、来源/版本及变更记录；缺失不等于零。币种统一人民币，金额保留两位小数；订购数量必须为整数。采购基准价已含税，首期不单独管理税率。单价保留两位小数，每行金额四舍五入至两位小数。

## 5. 价格规则与计算

### 5.1 规则配置

自有品牌报价首期只使用线下供货阶梯口径，每款商品可按品牌维护自己的档位，不显示线上供货价。客户贴牌针对客户与具体产品规格按需设置；创建客户时无需为所有产品建立价格。规则包含：适用对象（自有品牌或客户贴牌）、规格、数量单位、计价方式、有效状态/时间、规则版本和多个区间。客户规则查找不到时明确提示建立，不静默回退其他客户或通用价。自有品牌及客户贴牌均支持按品牌区分规则；同一适用范围有多个有效规则时阻止生效并提示，不自行猜测。

每个区间可选择一种计算方式：固定单价、基准价加固定金额、基准价百分比加价、基准价打折。不同档可选择不同方式。以 20% 表示加价 20%，以 90% 表示按基准价九折，数值必须清楚标注；每档只选择一种方式，不叠加。区间必须非负且有序，不重叠；边界明确；最低档以下提示调整规则或人工设价，不能自动套价。订购数量为整数；区间采用达到本档下限、未达到下一档下限的方式。

### 5.2 整批与分段

- 整批：按总订购量匹配区间，该单价作用于全部数量；货款为总数量 × 档位单价。
- 分段：各区间内的数量分别乘以该区间单价，相加得货款；展示每段数量、单价、金额和总额。需要显示单价时明确注明平均单价及精度，不用舍入后的平均价反推总额。

示例：1–999 个 110 元、1000 个及以上 105 元，订购 1200 个，整批总额 126000 元；分段总额 999×110＋201×105＝130995 元。规则出现未覆盖区间、缺少依赖价格或产生无效价格时不可输出完整候选金额；直接人工设价不需要基准价，百分比/折扣/固定加价依赖基准价。

价格计算必须在后端统一实现并返回明细，金额与百分比使用十进制精确计算，不能使用二进制浮点数作为最终金额依据。区间端点按本档下限包含、下一档下限不包含处理；单价及行金额保留两位小数，行金额四舍五入；测试覆盖临界数量、缺价及分段总金额。

### 5.3 基准价与价格变化

基准价更新后，固定单价保持不变，基于基准价的规则重新计算并提示复核；新报价使用最新有效值，已确认历史快照不变。草稿或待确认报价可由业务员显式按当前规则重新计算，受影响产品确认失效；确认时校验规则、基准价及组合组成版本，防止多人并发确认过期数据。报价生成后不可直接改价；已确认报价复制新版本后重新确认。

### 5.4 组合商品

以组合订购数量 × 每套组成用量得到组成项数量，按对应价格口径和阶梯计算；分段先算组成项总额再折算每套。确认人员可查看组合组成项参考明细；对外 Excel 仅显示确认后的组合商品整体价格，不展开组成项价格。缺价不能按零，不能把已知小计标成完整总价。允许在报价创建时直接录入成品组合价格并经过本次人工确认；是否将该价格保存为常用规则由有价格维护权限的人员选择。组合商品有独立阶梯价时优先使用，否则展示组成项计算的参考价；自有品牌报价使用组成项对应自有品牌价格，贴牌报价使用该客户与品牌对应的组成项贴牌价格；缺价明确提示，不自动换用其他口径。按当前报价单的组合数量计算，不与其他报价单或历史订单合并数量。

## 6. 报价流程与状态

1. 创建报价：选择客户、报价日期、报价类型（自有品牌/客户贴牌）、对应品牌与商品规格，设置数量或需展示的多个数量档。报价单拥有草稿及后续版本。
2. 获取候选价：带出适用价格规则，或在专门价格设置入口按需新建。缺基准价可直接设置固定价格；不允许把缺失默认为零。
3. 设置作用范围：客户首次建立价格默认选“保存为客户常用价格”，可改“仅本次”。界面必须明示影响范围，确认操作与长期规则保存动作留痕；不能静默将一次性优惠覆盖长期价。常用价格冲突需提示并明确是替换还是新版本，不能静默覆盖。
4. 规则变更：长期规则修改影响后续适用报价；报价创建后不能直接修改其价格。草稿或待确认报价需按当前规则显式重算，已确认报价通过复制新版本重新计算、确认。
5. 逐产品确认：每个产品的所有数量档同时展示，负责人一次确认该产品全部展示档。任一价格/数量/规则输入/商品配置发生影响报价的变化，受影响产品重新确认。缺少可计算候选价的档位不能确认。
6. 全部展示产品确认后，报价单方可标记已确认并对外导出；导出内容必须与已确认快照一致。参考报价也必须逐产品确认后才能对外导出，内部草稿不可伪装为对外正式报价。
7. 已确认报价变更通过复制新版本并重新确认，旧版本保留。记录创建人、确认人、时间、规则版本、商品与数量、价格明细和条款快照。

建议状态：草稿、待确认、已确认、已作废；状态转换、权限、数据写入与确认版本校验需在数据库事务内保证一致。对共享规则或商品更改不能反向改写已确认快照。

## 7. 报价单与 Excel

参考文件：[报价参考工作簿](../reference/毅诺采购合作参考报价单%20V1.0%2020261012.xlsx)的两个工作表仅作样式与字段依据，数字及客户条款不自动用于所有报价。

- 自有品牌（白牌）：只保留线下供货参考价，不显示线上价；展示品牌、客户、日期、产品型号/名称/规格及单位、供货价、建议市场零售价、建议首批量、交付说明及可维护服务/商务条款。支持多个自有品牌，并可按品牌配置价格。
- 客户贴牌：展示客户品牌、型号、名称、规格及单位、各数量档价格和货款、定制说明及可维护条款；数量档不能固定为 500/1000。分段计价需清晰标注各段、总额和平均价定义，不能套用整批单价列造成误导。

输出仅包含对外字段，不含采购基准价、财务成本、内部规则、计算参数及未经授权的备注。导出同一个 Excel 工作簿，分别设置自有品牌和客户贴牌页签；条款可以维护，建议首批量由业务员填写。建议零售价既可选择四个系统参考价之一，也可单独手工维护。采购基准价已含税，首期不单独管理税率；报价人员填写报价有效期。服务、交付及商务条款默认参考原表，报价时可修改，公司名称和联系人按实际配置。只制作一种报价类型时仍保留两个页签，另一页签为空。

## 8. 用户权限与并发

已确认三类角色：管理员、业务员（报价人员）、确认人员，同一人可兼任。权限包含基础资料维护、价格维护、成本查看、报价创建和报价确认；可在管理员页面为角色配置。只有具备确认权限的人员可以确认；业务员兼任确认角色时允许确认自己制作的报价。业务员获得相应价格维护权限后可维护价格。服务端检查权限；密码安全存储；操作日志不得记录密码或数据库凭据。确认时校验快照/版本，避免他人修改后仍成功确认旧内容。

## 9. 概念数据模型

以下是领域实体，不限定 ORM、表结构或最终字段：

- 用户、角色、权限、用户角色关联。
- 商品、商品规格、图片、组成关系。
- 客户、品牌、客户品牌关联。
- 基础价格及变更记录（采购基准价/出厂价、财务含税成本）。
- 价格规则及版本、数量区间、计价方式、适用对象、生效时间。
- 报价单及版本、产品行、报价数量档、价格来源、计算明细快照、客户/商品/条款快照。
- 报价单版本、逐产品确认记录及操作日志。

每项金额保持币种和单位信息，价格规则设置防重叠校验。保存数量、价格、金额时使用数据库合适的十进制类型；单价和行金额按已确认规则保留两位小数。客户数据和现有数据库内其他业务应隔离。删除/停用不得破坏历史报价关联；报价历史使用快照而不是依赖当前商品记录。

## 10. 页面与接口边界

页面：登录；商品/规格及组成；客户与品牌；基础价格；自有品牌及客户贴牌阶梯规则；报价列表；白牌/贴牌报价创建与人工价格输入；逐产品确认；Excel 导出；用户/角色与备份提示。

后端接口按领域提供：身份与权限、商品及组成、客户品牌、基础价、价格规则与报价试算、报价单及版本、产品确认、Excel 导出。设计统一的错误响应；对区间冲突、缺失基准价、规则不存在、并发版本冲突和无权限提供可读提示。接口 URL 以代码中的 NestJS 控制器为准。

## 11. 开发及验收顺序

1. 阅读并核对本规格、参考 Excel 与工作区指令；确认测试数据库隔离方式和凭据配置，不修改现有共享数据。
2. 搭建前后端项目、配置、安全与 PostgreSQL 连接；完成产品规格、客户、品牌的最小流程。
3. 实现独立计价模块，先验证固定价、加价、折扣、整批/分段、阶梯边界和缺价。
4. 打通单商品从资料、规则、报价、逐产品确认到 Excel 的完整流程，再扩展多档、贴牌、组合、历史和权限。
5. 完成跨用户并发、规则变更与快照、数据恢复、网络故障、Excel 内容和局域网访问验证。跨平台验证需逐系统真实运行；无法测试的平台如实报告。

核心验收：

- 同型号单只/双只不同规格不混价；基准价与出厂价仅维护同一数据，财务成本独立。
- 100 元基准价加 10 元为 110 元，加价 20% 为 120 元，打九折为 90 元；直接固定价可在基准价缺失时使用。比例含义已确认：20% 表示加价 20%，90% 表示按基准价九折。
- 1200 个按第 5.2 节的两个例子得到 126000 元和 130995 元；最低档以下及缺区间不可自动报价。
- 100 套、每套两个配件时，配件数量 200；分段结果先算总额再折算。
- 客户首次报价只配置所需产品；长期规则可复用，单次价格不污染长期规则；下次报价仍需人工确认。
- 同一产品多档一次确认，任何档位变化后失效；全部产品确认前不能对外导出。
- 基准价变化使比例结果重算并提醒，固定价不变，已确认历史快照不变；并发修改不允许确认过期价格。
- 两类 Excel 对外内容准确，无采购及财务成本；白牌无线上供货价。
- 备份/恢复覆盖图片和数据库，未授权用户不可查看成本；运行环境和网络故障有明确提示。

## 12. 已确认规则与当前交付状态

以下规则是后续开发和验收的确定口径：

- 统一人民币，采购基准价即人工维护的工厂出厂价；财务含税成本独立记录。价格金额保留两位小数，订购数量只能为正整数。
- 每个数量区间采用固定单价、基准价加固定金额、百分比加价或折扣中的一种计算方式；整批和分段计价都支持，数量区间连续覆盖并明确上下界。
- 缺少基准价或价格规则时允许在创建报价时录入本次数量档固定价格；生成报价后不可在报价单内直接改价。未确认报价可显式按当前规则重算，已确认报价需复制新版本后重新确认。
- 客户贴牌阶梯仅对有实际报价需求的客户、品牌和商品按需维护；自有品牌与客户贴牌使用各自价格规则。
- 每个产品的所有数量档一起展示，由具备确认权限的人员一次确认；全部产品确认后才能导出。组合商品对外仅展示成品报价，不展开内部组成价格。
- Excel 使用一个工作簿和两个报价页签，未使用页签为空；自有品牌仅展示线下供货价，不展示线上价。建议零售价可选择系统参考值或单独手工录入，建议首批量可手工填写。

**当前实现状态**：产品/配件/组合商品资料、图片、客户与品牌、采购基准价与财务成本、按需阶梯规则、整批/分段计算、组合商品计算、创建时人工报价、逐产品确认、规则/基准价版本校验和双页签 Excel 导出已落入代码。类型检查与生产构建均已通过。
本地 PGlite 在应用启动时创建数据库、执行迁移，并在没有用户时创建首次管理员；数据库以单连接处理请求，数据存放在应用主机。云端 PostgreSQL 首次初始化 SQL 位于仓库根目录的 `backend/sql/init.sql`，针对空的 `plm` schema，并登记初始迁移记录；使用其他 schema 时应使用根目录 README 中的迁移命令。尚未连接云端数据库；Windows、Linux、macOS 的真实部署和局域网访问仍需在目标机器验证。本文不授权修改其他 schema 或现存业务数据。
